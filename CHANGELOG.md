## 2026-11-05 19:10 EST (UTC−05:00) — YOOtheme Pro; Sophos UTM; Rails CVE

- **YOOtheme Pro:** Update the theme to [5.0.53 or later](black-october/details/yootheme-pro.md#remediation) on WordPress and Joomla. The Joomla! Project rates [CVE-2026-102785](https://www.cve.org/CVERecord?id=CVE-2026-102785) CVSS 4.0 10.0 Critical: before 5.0.53, a signed image URL can be reused to write a PHP file, with no login. Wordfence scores the WordPress theme 9.8. Unit 42 says the first webshell was written two days after the October 21 patch, and that the write returns HTTP 500 while the file is still saved. Look for `wp-content/uploads/yt` plus seven hex characters `.php`, and for `ALFA_DATA`. The update does not delete those files. It is not in KEV.
- **Sophos UTM:** Install the [manual RPM](black-october/details/sophos-utm.md#remediation) on top of 9.724, or move to Sophos Firewall. Sophos rates [CVE-2026-118633](https://www.cve.org/CVERecord?id=CVE-2026-118633) CVSS 4.0 9.2 Critical and CVSS 3.1 8.1 High: with email scanning on, a remote sender can run a command as root after repeating the attempt for a few minutes. UTM is end of life, so the fix does not arrive as a normal update. The installed fix is the hash of `/usr/bin/cssd`, not the 9.724 version string. Sophos Firewall is not this flaw. It is not in KEV.
- **Zyxel GS1900:** The [`.3` firmware](black-october/details/zyxel-gs1900.md#remediation) is still the fix. Binarly's November 3 blog says the exploit it recovered, `gs1900_bundle.tar.gz`, carries addresses for a June `.2` build, `2.90(AAHL.2)C0`. The same post publishes SHA-256 hashes for the JITTERLY backdoor and the SIXZUT rootkit. A hash match is that malware. It is not proof a given switch ran it. If the management interface was reachable on `.2` or earlier, rotate the admin credentials after the upgrade.
- **Langflow:** Previdian's single sensor now counts [9,013 attempts](black-october/details/langflow.md#timeline) against the MCP stdio flaw, from 53 addresses, last seen November 5. The November 4 count was 7,341. Previdian also recorded a public Nuclei template on November 4. These are attempts, not confirmed compromises. The fix is still 1.13.1 or later. It is not in KEV.
- **Rails:** MITRE assigned [CVE-2026-122006](black-october/details/rails.md#timeline) on November 4 and rates it CVSS 3.1 9.8 Critical. That is the Active Storage ImageMagick issue. ## 2026-11-05 11:30 EST (UTC−05:00) — Better Auth; OpenSSH on musl; cPGuard licenses; Delinea agent

- **Delinea Privilege Manager:** The [reporter's write-up](black-october/details/privilege-manager.md#detection) names the condition the advisory left out. The Windows agent's certificate check on TCP 5593 has an empty body, so a caller-generated certificate is accepted, and one callback runs PowerShell as `NT AUTHORITY\SYSTEM`. The proof was on the same machine, and the reporter rates that case 7.8; Delinea's score stays 8.7. The fix is unchanged: Windows Core agent 13.0.2064 or 12.0.5804, and block inbound TCP 5593 until then. It is not in KEV.
- **cPGuard:** [OPSSHIELD is re-issuing every cPGuard license key pair](black-october/details/cpguard.md#remediation), because the attacker holds copies. The November 3 disclosure already said this. It does not say you install a new license file yourself, and it does not say when the old key stops working. The server update is still 5.88.26 or later, and a server that was online during the November 2 window still needs its passwords, root SSH keys, and database secrets replaced.
- **Better Auth:** If the server loads the Expo plugin, upgrade `@better-auth/expo` and `better-auth` to [1.7.16 or 1.8.0-beta.5](black-october/details/better-auth-expo.md#remediation) and rotate the application secret. GitHub rates [GHSA-4wq4-2ppv-q3hg](https://github.com/better-auth/better-auth/security/advisories/GHSA-4wq4-2ppv-q3hg) CVSS 3.1 9.1 Critical, and MITRE publishes the same score on [CVE-2026-121802](https://www.cve.org/CVERecord?id=CVE-2026-121802). The plugin signs a caller-supplied value with the application secret, so someone who knows a user's email can change that email. The GitHub advisory, published November 3, says no CVE is known; the CVE record is November 4 and names every version before 1.7.16, which is wider than the advisory. Signatures made before the fix stay valid until the secret changes. A server that does not register `expo()` is outside the flaw. It is not in KEV.
- **OpenSSH:** On Alpine and other musl Linux where sshd checks passwords itself, upgrade and [restart sshd](black-october/details/openssh-musl.md#remediation). OpenSSH rates the workaround in 10.6p2 critical, and no CVE is assigned. An account with no password accepts any password of 257 to 1024 bytes, if some other account has a password. On Alpine, edge is `openssh` 10.6_p2-r0, 3.24 is 10.3_p1-r2, 3.23 is 10.2_p1-r1, 3.22 is 10.0_p1-r11, and 3.21 is 9.9_p2-r1, with packages back to 3.16. A source build takes 10.6p2. OpenWrt's optional OpenSSH package on the 25.12 branch is 10.6_p2; its default SSH server, Dropbear, is not affected. glibc Linux and OpenBSD are not affected. If you cannot update yet, set `PasswordAuthentication no` and restart sshd. The new package does not replace a daemon that is still running. On Alpine's tiny-cloud images, the `alpine` user can become root with `doas` once any account has a password hash. KEV does not apply, because no CVE is assigned.
